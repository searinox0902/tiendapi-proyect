# API Alegra Proveedor electrónico Documentation

> La API de Alegra Proveedor Electrónico te permite enviar facturas y nóminas electrónicas a la DIAN, sin tener que preocuparte por los temas complicados de la DIAN, nosotros nos encargamos de eso.

Append .md to any documentation page URL to get its markdown version.

Tipos de endoso: - **01**: Con responsabilidad del endosante - **02**: En blanco con responsabilidad del endosante - **03**: Sin responsabilidad del endosante - **04**: En blanco sin responsabilidad del endosante  Cuando hay más de un endosante, exactamente uno debe tener `isMandatingParty: true` (mandante).

- [Endoso en procuración (039)](https://e-provider-docs.alegra.com/reference/createprocurationendorsementradian.md): Endpoint para crear un evento de Endoso en Procuración en el RADIAN. Este evento endosa una factura electrónica de venta como título valor.  Tipos de endoso: - **01**: En procuración - **02**: En procuración en blanco
- [Cancelación del Endoso (040)](https://e-provider-docs.alegra.com/reference/createendorsementcancellationradian.md): Endpoint para crear un evento de Cancelación de Endoso en el RADIAN. Este evento anula un endoso de una factura electrónica de venta como título valor.
- [Pago de la factura electrónica (045)](https://e-provider-docs.alegra.com/reference/createinvoicepaymentradian.md): Endpoint para crear un evento de Pago de la factura electrónica en el RADIAN. Este evento registra un pago de una factura electrónica de venta como título valor.
- [Informe para el pago (046)](https://e-provider-docs.alegra.com/reference/createpaymentreportradian.md): Endpoint para crear un evento de Informe para el pago en el RADIAN. Este evento registra un informe para el pago de una factura electrónica de venta como título valor.
- [Endoso de Cesión Ordinaria (047)](https://e-provider-docs.alegra.com/reference/createordinaryassignmentendorsementradian.md): Endpoint para crear un evento de Endoso de Cesión Ordinaria en el RADIAN. Este evento endosa una factura electrónica de venta como título valor.
- [Protesto (048)](https://e-provider-docs.alegra.com/reference/createprotestradian.md): Endpoint para crear un evento de Protesto en el RADIAN. Este evento registra un protesto de una factura electrónica de venta como título valor.
- [Mandato (043)](https://e-provider-docs.alegra.com/reference/createmandateradian.md): Endpoint para crear un evento de Mandato en el RADIAN.<br>⚠️ Importante:<br>El tamaño total del archivo del contrato de mandato y la nota de vigencia no puede superar los <b>4 MB</b> en conjunto.<br>Si la suma de de ambos archivos excede este límite, la petición será rechaza automáticamente con <i>413 Request Entity Too Large</i>
- [Cancelación del Mandato (044)](https://e-provider-docs.alegra.com/reference/createmandatecancellationradian.md): Endpoint para crear un evento de Cancelación de Mandato en el RADIAN. Este evento anula un mandato de una factura electrónica de venta como título valor.
- [Endpoint para generar un reporte por rango de fechas](https://e-provider-docs.alegra.com/reference/triggerdaterangereport.md): Dispara la generación asíncrona de un reporte de documentos electrónicos para un rango de fechas. El reporte se ejecuta en una tarea en segundo plano. Use el endpoint GET /reports/{requestId} para consultar el estado y obtener las URLs de descarga cuando esté listo.  Restricciones: - El rango máximo permitido es de 92 días - La fecha de inicio debe ser anterior a la fecha de fin - Si se envía callbackUrl, se valida que sea alcanzable  Retención: - Los archivos del reporte y su registro se eliminan automáticamente después de 60 días. Si necesita el mismo reporte después de este periodo, deberá generar uno nuevo
- [Endpoint para consultar el estado de un reporte](https://e-provider-docs.alegra.com/reference/getreportstatus.md): Retorna el estado actual de un reporte solicitado previamente. Si el reporte está completado, incluye URLs prefirmadas para descargar los archivos generados (válidas por 15 minutos). Si el reporte falló, incluye la descripción del error. Los reportes tienen una retención de 60 días; después de este periodo el estado será EXPIRED y los archivos ya no estarán disponibles. Para obtener los datos nuevamente, deberá generar un nuevo reporte.
